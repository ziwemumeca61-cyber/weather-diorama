## 一、提交前检查清单

| 项 | 位置 | 状态 |
| :-- | :-- | :-- |
| AppID 已填 | `project.config.json` → `appid` | ⬜ 需替换 `REPLACE_WITH_YOUR_APPID` |
| 云环境 ID 已填 | `miniprogram/app.js` → `wx.cloud.init({ env })` | ✅ `cloud1-d5got2635691af859` |
| 云函数已部署 | 右键 `cloudfunctions/weather` → 上传并部署 | ⬜ 每次改完要重新部署 |
| 云函数超时 ≥ 20s | 云开发控制台 → 函数配置 | ✅ 已调整（国外 API 延迟高） |
| 定位权限声明 | `app.json` → `requiredPrivateInfos` / `permission` | ✅ 已配 `getLocation` |
| 真机预览通过 | 开发者工具 → 预览 → 手机扫码 | ⬜ **必做**，模拟器正常不代表真机正常 |

### 为什么不需要配「服务器域名」

天气数据由**云函数**转发（`cloudfunctions/weather` 里用 Node `https` 请求 Open-Meteo），小程序端只调 `wx.cloud.callFunction`。云开发调用不走 `request` 合法域名校验，因此**不需要有备案的域名** —— 这是个人主体能做实时天气的关键。

## 二、基本信息（填在 mp 后台）

- **名称**：3D微缩城市天气
- **简称 / 昵称**：微缩天气
- **服务类目**：`工具` → `天气`
- **简介**（建议文案）：

> 用 3D 微缩城市模型可视化实时天气。搜索或定位城市，屏幕上会立起一座该城市的立体模型，配上当地标志建筑；下雨有雨滴、下雪有飘雪、起雾有雾气笼罩街道，入夜楼宇亮灯。

## 三、隐私保护指引（必填）

小程序用到了**位置信息**，必须在《小程序用户隐私保护指引》里声明。

| 收集的信息 | 用途说明（可直接用） |
| :-- | :-- |
| 位置信息（`wx.getLocation`） | 用于获取你当前所在城市的实时天气。仅在你主动点击「定位」按钮时获取，不会后台采集、不会存储、不会提供给第三方。 |

补充说明要点：

- 位置只在**用户主动点击定位按钮**时获取一次
- 经纬度仅传给自有云函数用于查询天气，**不落库、不留存**
- 不获取用户身份信息（没有 `wx.login` 授权登录）

## 四、提交审核时填的内容

- **功能页面**：首页（唯一页面）
- **测试账号**：不需要（无登录）

> 本小程序为天气查询工具。首页展示一座程序化生成的 3D 微缩城市模型，并叠加实时天气信息。天气数据来自 Open-Meteo 公开天气接口，通过微信云开发云函数转发获取。定位功能仅在用户主动点击「📍」按钮时触发，用于查询当前城市天气，不存储任何位置数据。小程序无用户登录、无内容发布、无社交功能、无支付功能。

## 六、变现：流量主

- **个人主体可以开通流量主**（这是选原生小程序路线的主要原因）
- 需要小程序**累计独立访客（UV）达到门槛**（❓ 通常说法是 1000，以后台实际提示为准）
- 开通后可在小程序里投放 banner / 插屏 / 激励视频广告
- **微信支付个人主体开通不了**，所以短期内变现只能靠广告

### 建议的广告位

在不破坏 3D 观感的前提下，最合适的是**底部面板下方的 banner**，或者切换城市时的**插屏广告**（频率要克制，否则影响留存和审核）。

> 广告代码目前**尚未接入**，等 UV 达标、流量主开通后再加。

## 七、常见驳回原因与应对

| 驳回原因 | 应对 |
| :-- | :-- |
| 类目与功能不符 | 确认选的是 `工具 → 天气`，不要选成 `生活服务` |
| 未声明隐私政策 / 位置用途 | 按第三节填写隐私保护指引 |
| 获取位置无必要性说明 | 在审核备注里写明「仅用户主动点击时获取，用于查天气」 |
| 功能过于简单 | 强调 3D 可视化 + 多城市地标 + 天气特效，不是纯文字天气 |
| 内容涉及地图 / 位置服务资质 | 本小程序**不展示地图、不提供导航**，只用经纬度查天气；如被问及可如此说明 |
